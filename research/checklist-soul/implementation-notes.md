# 聚魂 execution contract

Source implementation only. No tests, review, build, restart, runtime observation, game action, or network mutation was performed for this change.

The installed Assembly-CSharp.dll SHA256 was read as C1C8EBAC7DDEF4173C873A00774975A5CA366F95B19164C4CA775165EB994911, matching data/campaign-research/input-hashes.json. The installed dbdata.dll schema was decompiled read-only: _general_soul_start_mode has byte type, uint price, uint require_level, int free_times, byte nolimit_viplevel, uint gather_rate. Runtime template VALUES are deliberately not inferred; each native observation reads the installed loaded templates, and admission re-reads the selected quotation before invoking stock code.

GeneralSoulGatherUI.cs.txt DrawGatherButton lines 730-806 uses independent blue/purple counters. Purple FREE eligibility is level OR VIP. The branch `array[i] || i == 1` still offers ordinary paid purple when free eligibility fails; RequestGather lines 1636-1678 has no type-2 level rejection. Therefore free_unlocked and start_available are distinct. The latter denotes the ordinary stock entry, not sufficient funds. An unqualified purple start uses ordinary money and cannot be labeled free. Modes 1 and 2 are admitted only with fresh type and gather_rate==1 checks. Other, batch and premium modes remain outside this protocol.

DailySoulExecutor.execute(5, character_id=..., expected_cycle=..., expected_current=..., expected_required=..., blue_count=1, purple_count=1, free_only=True) executes one aggregate. In daily mode each count is at most 1; the selected character daily used_today must be zero, the color must be free-unlocked, its own free_remaining must be positive, and its current start_cost must be zero. Never substitute blue for unavailable purple. Each selected color is considered even when activity #5 is full. Known skip reasons are soul_color_locked, soul_daily_color_done, soul_free_exhausted. Unknown eligibility is soul_color_quote_unavailable, never an exhausted quota.

The manual coordinator accepts each integer count 0-100, total 1-100, and calls free_only=False. It can consume remaining free starts then ordinary paid starts, including paid purple without free qualification. Each new round re-observes the actual selected quotation and balance. There is no gold start, gold growth, exchange, batch RPC or arbitrary RPC path. Growth retains soul_strategy.choose_soul_action; this empirical stopping rule is not mathematically optimal. Daily extra gathers after activity saturation retain immediate harvest; manual gathers still use the ordinary coin strategy.

One operation owns one panel across all rounds. Native action next is admitted only after the previous harvest is verified. It calls the installed stock SetSubUI(existing panel), whose same-panel behavior is a no-op; it does not close/reopen or issue a game request. Each round resets only its own quote/counter/callback witnesses. The plan closes the owned panel exactly once after its last round. Unknown command results are never retried or followed by a speculative new gather. Controller stop recovery may close a quiescent owned panel, without claiming the unresolved gather completed.

Each 517 callback is bound to its selected mode and callback argument, exact ordinary-money delta, selected used counter, unchanged other-color counter and premium/exchange invariants. Selected purple is no longer incorrectly treated as an immutable premium counter. Each manual harvest (518) or stock auto-harvest carried by ordinary growth (519) requires exact award inventory readback, settled stock board and capped activity accounting. After saturation, unchanged activity readback without another 355 push remains allowed; callback, inventory and resource evidence still prove the gather independently.

DailySoulResult retains its original fields and adds blue_completed, purple_completed, coins_spent, rounds, skipped, quote, current_color. rounds is a tuple of frozen SoulRoundReceipt values with round (starts at 1), color, mode, start_cost, coins_spent, growth_count, free_before, free_after, progress_before, progress_after, start_verified, harvest_verified, auto_harvest, start_sequence, settle_sequence, board_before_growth, award. settle_sequence identifies the 518 harvest or the 519 auto-harvest command. award is the actual [blue,purple,orange,red] inventory delta. Each observed initial board is retained, never reconstructed. The historical two runs that spent 22000 ordinary money did not capture board history; this change does not create one.

skipped is a tuple of frozen SoulSkip(color, reason). After one or more rounds and verified final close, daily returns COMPLETED/soul_plan_completed with cleanup VERIFIED_CLOSED. When no daily color is eligible it returns ALREADY_COMPLETE/soul_no_free_starts, progress_after=baseline, cleanup NOT_NEEDED; this describes completion of the free-start plan, not the activity counter. Manual skips or insufficient money after some rounds can return PARTIAL with verified cleanup; they do not falsely claim requested counts completed. All result fields exist on failures. On UNKNOWN, coins_spent contains only verified actual spending; a pending unverified request may have spent more, so it is not a proven final bill.

SoulCoordinator(objects, runner, data_dir) exposes start(blue_count,purple_count), refresh_quote(), pause(), resume(), stop(), close(), is_active, is_paused, is_shutdown, snapshot and events. events contains frozen SoulRunResult values; snapshot is dataclasses.asdict(result). Fields: status, reason, blue_requested, purple_requested, blue_completed, purple_completed, coins_spent, cleanup, character_id, cycle, operation_id, current_color, rounds, skipped, quote, ledger_path. Execution records are written under data_dir/soul-runs/<operation_id>.json. A ledger-write failure is explicit in reason. Read-only quote refresh uses QUOTING then QUOTED, does not open a game panel or issue LoginUI.Refresh/daily-state-refresh, and creates no execution ledger.

quote is {available,reason,character_id,cycle,coins,growth_cost,growth_variable:true,blue,purple}. Each color is {known,unlocked,free_unlocked,start_available,reason,used_today,free_remaining,start_cost,paid_start_cost}. unlocked aliases free_unlocked. Missing template/boundary observations stay null/unknown. growth_cost is one ordinary growth quotation; total growth expense varies with the board. A quotation never promises an exact aggregate bill.

The daily-soul-command wire is TIMED_FIELDS plus soul_mode=1|2 and free_only=0|1, with the additional next action. Protocol.cs and Probe.cs changes are restricted to those soul fields and their final GUI binding. Other contributors' changes are preserved.

Runtime success, actual current eligibility/price values, paid purple behavior on the server, multi-round panel retention, final cleanup and real receipts remain UNVERIFIED until the controller builds and runs the app. Native/Python integration and GUI/workflow integration must be deployed together. No test or review result is claimed.

Pause closes Python admission while fresh native ownership/quote observations continue. Settled READY frames have no request timeout; pending/opening/closing requests retain finite deadlines. A pause cannot authorize a second request after an unknown result.
