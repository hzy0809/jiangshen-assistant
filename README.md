# 将神助手

面向 Windows、按需运行的游戏助手脚本，提供本地图形入口。v0.4.0 支持征战、挑战、固定新将教学、成长任务、日常及可复用装备/灵兽培养。征战沿当前主线挑战，**本轮连续失败三次后停止，胜利后计数归零**。挑战按本轮累计失败三次停止，胜利不清零。

## 启动

双击 **启动助手.cmd**。也可以在本目录运行：

```powershell
python -m jiangshen_assistant
```

要求 Windows 10/11、Python 3.10+（包含 tkinter）；不需要安装 pip 依赖。启动脚本会从 PATH 中查找 Python，并使用同目录的 pythonw 启动图形窗口。

侧栏直接进入征战、挑战、培养、日常或聚魂；助手自动查找和连接游戏，连接状态显示在顶部，自检在“诊断”。培养页选择星灵、灵兽上贡、成长任务或装备后，只显示该功能的操作和参数。

Ctrl+0 打开账号；Ctrl+1–3 切换征战、挑战和培养，Ctrl+5–7 切换诊断、日志和设置；Ctrl+8 切换日常，Ctrl+9 切换聚魂。窗口标题标明当前页面及培养功能，F8 和 Esc 保持停止用途。

每次手动按“开始”都读取当前游戏页面、角色、任务、进度及资源，建立一轮新的执行状态。账号轮次运行时，确认游戏或登录器进程意外退出后可按原配置尝试恢复；已派发但结果未知的任务不会自动重放。助手自身退出后不会自动重启或恢复旧轮次。界面日志显示本次启动的事件。绑定仅选择游戏窗口，无需提供账号密码。

## 账号

1. 打开“账号”，选择“新增账号”，在“账号信息”中填写登录账号、密码和区服名称，并按启动器中的网页版、三端版或移动版选择区服分类。账号 ID、区服 ID 和角色 ID 可以留空；本轮自动登录后会读取当前游戏身份。已有 ID 会在执行前核对，不一致时停止该账号。
2. 在账号列表中勾选要加入本轮的账号。在“任务配置”中逐项启用任务并填写该账号的选项；日常子项按用途分组。灵兽上贡的目标和次数在“灵兽上贡”选项中设置，日常选择上贡时也使用这些上限。独立聚魂可分别设置蓝魂、紫魂次数，免费次数用尽后可能消耗钱币。运行期间不能修改本轮账号选择。

每个账号的日常子项、同盟捐献档位、商铺生产时长及其他任务选项各自保存；修改后自动保存，数字无效或写入失败时会显示错误。切换账号前会完成待保存的任务配置。账号身份信息仍可用“保存”按钮保存。独立“日常”页面的选择单独保存在全局设置中，不会覆盖账号配置；账号中的日常任务也不使用独立页的选择。
3. 保存后选择“开始一轮”。“执行记录”逐账号显示任务、结果和等待原因；暂停、继续和停止作用于整轮。账号、密码和选项保存在 `data/account-profiles-private/profiles.json`，密码为明文文件，目录权限限制为当前 Windows 用户和系统；同一用户进程和管理员仍可能访问。密码输入框留空会保留原密码，勾选“清除已存密码”并保存可清除。

已有绑定会话经账号、区服和角色核对后可使用，状态标为已有会话，不代表自动登录成功。需要切换账号时，助手先清理连接，再正常退出当前游戏和可确认由其启动的登录器；不会强制结束进程。新会话使用已安装的正常登录器；验证码、共享登录状态、无法识别的控件或服务器等情况需要本人在登录器处理并按界面提示确认。窗口归属或退出无法确认时，停止切换并显示原因。

能安全释放由本轮启动的会话时，较长的征战会排在其他账号的短任务之后；现有非本轮会话不被助手关闭。需要保持在线的日常冷却会显示等待原因，并阻止不安全的切号。当前角色未下发的日常进度不会按零或完成计算；聚魂和炼魂还会分别读取游戏的原生入口解锁状态。

精英挑战需要填写实际可用的关卡编号和星级，默认日目标 10 次。打开游戏中的精英关卡列表并等待顶部显示已连接后，可在精英挑战选项里读取和选择当前可进入的关卡；开始时会再次核对。由于剩余次数可能包含购买或跨日结余，只有观察到可靠的每日刷新基线后才能确认已用次数；无法确认时会停止，既不自动购买次数，也不重发结果未知的战斗。账号任务中的征战沿用独立征战的成长流程：出现当前成长提示时处理并领取该任务奖励；成长可能消耗资源，不使用独立培养任务的预算。旧账号配置中单独的成长、领奖开关保留用于兼容，不会单独启动征战。账号任务、正常登录和精英挑战以当前实际运行结果为准，多账号切换尚待实机验证。

## 当前可用

- 启动后持续自动查找标题包含“将神”的 `js.exe` 游戏窗口；排除登录器，单窗口自动绑定，角色就绪后自动连接。多个匹配窗口时，在顶部选择要使用的窗口。
- **征战**页：开始、暂停、继续、停止；显示当前目标、连续失败和运行状态。开始征战会自动连接调用接口。
- **挑战**页：只推进尚未通关的普通关卡，胜利后继续、失败后重试，本轮累计失败三次停止，胜利不清零。跳过精英星级，不购买次数或资源；启动时读取当前挑战页面，当前无可进入的普通关卡时停止。支持暂停和 F8 停止。
- 只推进尚未通关的主线目标；按游戏实际通关进度转入下一节点，已通关关卡不重复挑战。失败时可重试，连续三败停止。
- 按游戏正常规则出战；固定新将教学可正常上阵、自动装备并确认布阵。
- **培养**页：执行当前成长任务，或单独领取唯一已完成未领奖的任务；装备强化/升阶可填写目标和资源预算，灵兽上贡设置目标与上贡上限。
- **星灵 · 自动激活**：使用当前战魂逐次激活，确认本次星灵进度和战魂变化后继续；战魂不足下一次激活或星灵全部激活时停止。自动关闭本轮产生的解锁提示，不进入布阵、不购买资源。支持暂停和 F8 停止。
- **灵兽上贡**：设置目标阶、星（各 1–10）和一个上贡上限（1–100 次）。每次消耗 1 颗桃子，上贡上限也就是桃子消耗上限；取消上限后用完本轮现有桃子即停。达到目标、用尽次数、桃子耗尽或满级，任一条件先满足即停止。普通免费进阶自动继续，不使用元宝。支持暂停和 F8 停止。
- **日常**页：逐项勾选本轮要执行的项目，可全选或清空；勾选和同盟捐献档位自动保存，空选不能启动，结果显示未启用项目。旧版全局设置首次打开时默认全部不选，原窗口、热键等设置保留；同盟捐献默认 10 万钱币，也可选择 1000 钱币或 80 元宝。日常上贡使用“培养 → 灵兽上贡”当前显示的目标和桃子次数上限，可从日常页“上贡选项”直接进入配置。
- **日常选择的依赖**：“签到及领奖”按签到页状态分别处理签到、俸禄、竞技宝箱和积分宝箱，不会启动竞技场或积分赛挑战。收获铭石目前要求同时选择“击败天神”。精彩活动仅领取免费奖励；七进七出需要消耗资源或成本未知时跳过。
- **礼包领取**：检查主城顶部的礼包，只领取当前已到时间的一档，不等待后续档位。该选项按账号保存并默认启用，也可关闭；它与“在线奖励”抽奖是不同入口。
- **主城**：可选择收取灵气树、收取及生产钱币商铺、收取已击败的小妖。每个账号可选择只收取，或在所有商铺生产同一时长档的钱币商品（20 分钟、1 小时或 12 小时）；新选项默认关闭，启用后初始时长为 1 小时。生产使用灵气，不自动使用元宝或即时生产。灵气树可能因容量不足而跳过。小妖仍可领取时会再次尝试；没有回包时按设置视为完成，并在记录中注明。单轮最多发起 64 次小妖收取，相关结果生成后保存在 `data/city_activity_runs/`。
- **复仇魔王**：选择该项时处理当前自己的魔王，包括战斗或收取已击败魔王的奖励；每日进度已满时也会处理当前目标。冷却中或没有当前目标时不等待刷新。
- **日常路线**：已勾选的名将试炼争取通关，排位竞技场争取当日钱币和声望奖励，分组积分赛使用自然次数和免费刷新；免费聚魂按当日蓝魂、紫魂资格执行，木人使用免费次数，炼魂补足共享的 10 次普通经验兑换。抄录和在线奖励先处理当前可做的次数，再等待冷却并继续，直到免费次数用完或日常刷新；等待可暂停或停止，不使用元宝加速。签到页宝箱只领取免费奖励，跳过元宝找回。
- **聚魂**页：分别选择蓝魂、紫魂的次数，合计 1–100 次；可刷新查看免费次数和开局、成长的钱币报价。免费次数用完后按当前钱币报价开局，不使用元宝。纯紫魂入口沿用当前角色已保存的策略；未保存时使用内置有限成长规则，根据盘面和钱币余额决定收获，尚未证明收益最优。
- **训练妖魔**：游戏提供一键秒杀特权时优先使用；否则从当前未冷却的低等级目标开始挑战，并在游戏允许时跳过战斗演出。清完后自动使用免费召唤，直到没有免费次数。
- **战斗演出**：助手发起的受支持战斗在真实战报和必要对象就绪后尽早查看或请求结果，按游戏回包结算；服务端仍可能要求等待。

- 装备任务读取实际要求，选择当前阵型中已穿戴、归属一致的装备逐次培养；达到任务等级后停止培养，继续检查和领奖。
- 收到当前成长任务提示时执行该项固定流程，完成并领奖后返回征战；等级和关卡要求交回征战推进，尚未实现的要求留待逐项增加。
- 征战、剧情和成长流程采用事件订阅，游戏状态变化后唤醒对应协调器；空闲时只保留心跳和身份监控。详见 [事件调度](docs/event-driven-workflows.md)。
- 剧情优先使用游戏自带的“跳过剧情”，保留游戏正常触发和结束回调；非强制提示保留配置，未知教学暂停等待处理。
- 征战与挑战的正常剧情、功能提示沿用游戏已有的继续、确认和动画流程。原生适配层统一给出可操作、等待或不支持的结果，Python不再另行判断提示图标的尺寸、纹理、布局及载入标志；本轮战斗关联、失败计数、操作去重和资源使用范围仍由脚本保持。持续过场等待使用同一个30秒预算。
- 每场只提交一次攻击，按本场最终回执或有完整关联的主线通关进度确认结果；进度证据只确认胜利。普通失败即使没有保存战报编号，也按同一场战报和结果页计入连续失败，关闭“如何变强”建议后继续，三败时停止。无法确认本场结果时保留记录并停止后续发起。
- **自动连接**：发现窗口后先只读等待角色就绪，再载入调用组件；等待、连接和需处理的原因显示在当前页面。角色及资源读数继续保留在命令行状态中。
- **停止与恢复**：F8、Esc 和停止按钮停止调用并核对清理结果，同时暂停该游戏的自动连接；下次明确开始玩法或选择游戏窗口时继续连接。普通连接失败会按间隔重试；当前游戏进程的原生接口明确要求重建时，停止重复连接并显示重新打开游戏的原因，确认旧进程退出后可自动接入新窗口。旧业务的未知结果独立保留，不会随重连被重放或改成成功。
- **诊断**页的只读自检：验证绑定窗口身份和后台任务执行，不向游戏发送点击或按键。
- 任务暂停、继续、停止；全局 **F8** 和助手窗口内 **Esc** 停止。
- 本地 JSON 配置、界面日志与轮转日志文件。

运行日常期间请勿同时在游戏内手动操作同一项活动，以免无法区分进度变化的来源。

打开助手后会持续查找游戏，不需要手动刷新或连接。先开游戏或先开助手均可；游戏进入角色后自动连接。连接期间保持游戏处于稳定主界面，等待顶部显示“游戏已连接”。助手直接读取对象和调用游戏方法，不采集截图或显示画面预览。

征战请在“征战”页按“开始征战”。暂停、继续只作用于当前运行中的任务；停止会阻止下一场发起，已经开始的战斗仍由游戏继续结算。再次开始时按当前页面重新决定下一步，失败计数从零开始。若全局 F8 显示不可用，可用停止按钮或助手内 Esc。

自动推进期间保持助手独占征战操作，避免同时手动开战或切换关卡。本轮动作按自己的回包和当前界面变化确认；无法确认时结束本轮并说明原因，不自动重发。新任务读取当前游戏状态，旧日志中的未知结果不阻止新任务。

窗口失效或调用超时会显示错误。关闭助手时会停止后续操作，等待任务和调用会话完成清理。

## 命令行控制

在 `G:\development\enjoy` 下运行：

```bat
助手CLI.cmd status
助手CLI.cmd status --compact
助手CLI.cmd restart
助手CLI.cmd run campaign
助手CLI.cmd run daily --donation 100000
助手CLI.cmd run daily --option shop_duration=3600
助手CLI.cmd soul-quote
助手CLI.cmd recover-soul
助手CLI.cmd reconnect --compact
助手CLI.cmd soul-harvest --compact
助手CLI.cmd run soul --option blue_count=3 --option purple_count=1
助手CLI.cmd pause
助手CLI.cmd resume
助手CLI.cmd stop
助手CLI.cmd exit
```

`status` 返回当前窗口、连接和任务状态；`auto_connection` 给出自动连接阶段、等待原因及候选窗口，`daily_selection` 给出独立日常页的子项开关、捐献档位和商铺生产时长；`run daily` 使用该页已保存的勾选，空选拒绝启动，不指定参数时沿用已保存选项。`shop_duration` 以秒为单位，接受 0（只收取）、1200、3600 或 43200。`soul-quote` 异步读取聚魂报价，结果在 `status.workflows.soul.snapshot.quote`；`restart` 正常关闭助手并重新启动，`exit` 正常关闭助手。`run` 也接受 `challenge`、`growth`、`growth-claim`、`equipment`、`tribute` 和 `star`；聚魂及培养参数可用重复的 `--option 名称=值` 传入，例如 `run equipment --option equipment_id=123 --option desired_level=10`。`bind --index 0` 可按 `status` 所列顺序选择游戏窗口，也可用 `bind --hwnd 0x...`；选择后自动清理原连接，再连接目标窗口。命令输出 JSON；失败时返回非零退出码。

`status --compact` 保留状态、进度和 `ledger_path` 等账本路径，以计数代替工作流历史明细；完整原始回执可从返回的账本路径读取。默认 `status` 仍返回完整状态。

`run`、`soul-quote`、`soul-harvest`、`reconnect`、`recover-soul`、`pause`、`resume`、`stop`、`bind`、`workflows` 和 `workflow` 也支持 `--compact`，以缩小命令回执中的状态。命令响应编码或传输失败时，动作可能已经被接受；先用 `status --compact` 核对当前状态和账本，不要直接重发消费请求。

聚魂单次运行可通过 `--option max_growths=3 --option protect_count=2` 等参数选择当前策略的成长上限和保护条件；还支持 `policy_version`、`protect_level`、`high_level_count`。`policy_version=joint-value-v3` 配合 `model_path` 指定当前角色的真实已结算账本，支持蓝魂和紫魂入口，并分别记录混色盘面的各色收益。预测使用首段八槽联合样本与连锁结算，以一次完整收费请求的净收益决定继续或收获；未知奖励或覆盖不足时保守收获，已定价高色魂的风险纳入整盘估值。v3 使用成长上限，不使用旧策略的高等级球数量保护条件。钱币预算仍逐步核对。收益模式默认不探索；显式探索属于额外信息采集，需要独立费用与损失额度，不能视为已证明盈利。这些显式参数只作用于本次运行，优先于角色已保存的策略；资源总上限通过 `--policy-file` 指定。

新模型清单可使用 `schema: "soul-joint-receipts-v1"`、`character_id`、`mode: 1`（蓝）或 `2`（紫）及绝对路径数组 `additional_ledgers`。完整回执索引保留来源 SHA256、角色、入口、报价、去重与排除原因；奖励映射冲突不会合并。运行账本中的成长包含 `chain_settlement`，收获包含 `native_harvest_receipt` 及原生资源/库存前后值。混色连锁保留可能终盘和每色收益范围，不假定均匀选球，也不套用纯紫盘固定减14。历史账本不授予当前动作权限。

可选的 `data/soul-policies/<character_id>.json` 以 `schema: 1`、当前 `character_id`、`mode: 2` 和完整 `policy` 保存紫魂默认策略；蓝魂使用 `<character_id>.mode1.json`、`mode: 1`。v3 的 `model_path` 使用绝对路径。未显式传入策略的单入口请求，在本次连接身份与新鲜报价角色一致后读取对应文件；坏配置会在收费开局前阻塞。一次同时选择蓝、紫的请求、只读报价和日常免费聚魂不套用单入口默认策略。运行记录中的 `policy` 和 `policy_source` 标明实际选择。

v3 单入口运行全部完成、关窗核实且原始账本原子落盘后，才把账本绝对路径幂等追加到同角色、同入口模型的 `additional_ledgers`；下一次加载仍从原始回执核对，不直接改写统计或概率。旧 `purple-joint-transitions-v1` 清单继续仅接收紫入口。追加失败单独记录为 `model_update_error`，保留已确认的游戏结算结果。保存策略和学习样本不会启动、预约或恢复聚魂，也不保存资源授权；每次仍受本次钱币预算及资源策略约束。

`exploration_mode=post-burst-v1` 将探索限制在自然爆损后的低盘：当前估值不超过40紫、至少3个紫槽为1～3级，且模型仅因覆盖不足停手。`explore_growths` 在该模式下每局最多2次；`exploration_money_limit`、`exploration_loss_limit` 分别限制整次运行的探索钱币与毛损失，正收益不补回损失额度。每次探索前须有足够钱币及覆盖当前整盘估值的损失余量；恢复探索净增不大于0便收获。具体回执记录在决策的 `joint_value.post_burst_exploration`。

`reconnect` 建立当前游戏的连接，`recover-soul` 保留为它的兼容入口。历史未知结果、未收获盘面、业务报价和角色资料不阻止重连；它们保留为独立的业务诊断。连接正常不代表旧请求成功，也不重放旧请求。

聚魂页的“收获当前牌面”与 `soul-harvest` 使用同一调度入口。连接后核实当前盘面稳定、旧执行者与回调已退出、没有在途请求，再用新的操作身份接管、收获并关闭；显式收获不会成长。普通聚魂遇到已有盘面时则接管后进入同一个收益决策器，按真实报价与预算决定新的成长或收获。账本标记接管来源及新发生的费用，旧局的费用与未知状态仍保留，不重放旧请求，不把接管当作已发出新的收费开局。

日常是玩法编排集合。独立聚魂与日常聚魂都调用 `SoulExecutor` 和同一个策略解析器；日常只传入次数、免费开局限制及资源授权。日常清单进度仅是可选观察，不参与聚魂成长、收获或连接准入。免费开局限制只禁止收费开局，成长仍按本次钱币授权核对。

混色盘面统一按蓝魂数量 + 5×紫魂数量 + 10×橙魂数量估值，再计算完整成长与连锁后的收益界。不会把各色分别取到的极值拼成不存在的盘面，也不因为可能损失高色魂一律停手。策略比较本次授权范围内的收获价值；外部调用方设置的6000等数量限额由其按实际对应颜色的收获累计，作为停止条件，不驱动持续消费，也不折算成等价魂值。

机会成本依据剩余预算和本次计划中尚未执行的开局计算。当前已付开局费是沉没成本；后续同入口开局采用“重开后立即收获”的参考策略，用已核对的真实初盘估值，比较本次成长前后的参考未来价值。该方案不包含未来盘的成长收益，不代表全局最优。如果没有后续合法开局，或这笔成长费用不改变参考策略可开的局数，参考机会成本为0。缺少计划上下文、报价或初盘证据，以及涉及不同入口的未来资金分配时，明确记录回退原因，使用历史完整付费局收益率作为近似；不把该近似称为精确钱币价值。预算、免费开局和购买授权在每个真实动作前仍独立核对。

当前决策保留有界两步继续/收获前瞻。子状态先检查机械覆盖，不支持的状态立即返回收获下界和未知上界，不执行昂贵投影；已全部满级的子状态只能收获，上下界相同。根状态保留原始投影诊断及完整来源权重。`continuation_prediction` 分别记录 `candidate_states`（含重复的后继调用）、`admission_checks`（缓存未命中的检查）、`cache_hits` 和 `projected_child_states`（实际进入投影的子状态，含之后失败的投影）；兼容字段 `expanded_states` 与最后一项相同。32个名额只限制实际投影子状态，0.4秒继续计算预算仍保留；时间、投影名额截断与证据不足分别记录。未展开状态保留立即收获这个可行选择。它是有限模型决策，概率、工程余量与实际增收效果仍有未验证部分。

也可在本项目目录使用 `python -m jiangshen_assistant` 调用相同命令。助手首次启动或更新后，需要使用新版助手进程才能接收控制命令。

调用接口限定当前已验证的游戏版本与本项目路径。游戏更新、项目移动或版本校验失败时会拒绝连接，需重新适配验证。若恢复结果为 `UNKNOWN`，保留现场并正常退出游戏后再连接，不要删除会话文件强行重试。断开会销毁辅助组件、移除钩子；已载入的 DLL 和托管程序集会保留到游戏进程退出。

## 玩法工作流

“日常”页的“领取积分宝箱”可单独执行正常的“积分赛 → 宝箱”流程，不改变日常勾选；CLI 使用 `python -m jiangshen_assistant run point-reward`。启用签到及领奖时，签到页尚未发出请求的可领积分奖励也会在签到页收尾后转入这一流程。流程仅领取当前免费奖励，逐笔核对正常回包和奖励列表变化，关闭领奖及宝箱窗口后返回主城；历史元宝找回、积分赛挑战和对手刷新由各自原有流程处理。

天神采用同一页面会话，逐场确认战斗结算和奖励关闭后再选择下一目标，整组结束或战败后正常返回。铭石只在明确未调用且获得新状态的短暂拒绝时有限重试；已发送但结果未知的领取不会重发。实现和实机覆盖范围见[天神、铭石与地宫记录](data/divinity-fixes-20261112/result.md)。

CLI 可用 `run account_plan --option account_id=<配置ID> --option daily_item=divinity` 单独执行所选账号的天神；`daily_item` 也支持 `mingshi`、`grave` 和 `online_gift`。只允许当前已选择、已启用相应日常项的账号；铭石会同时保留天神前置。这些范围仅作用于本次运行，不保存账号选择或任务配置。

`run account_plan --option account_id=<配置ID> --option login_only=true` 仅登录一个当前已选择的账号，核对区服和角色身份后保留游戏，不派发任何玩法，不保存账号选择或任务配置；不能与其他账号任务范围合用。

“运行”页（Ctrl+R）集中显示当前场景、执行中的玩法和等待队列。各玩法页的目标与操作保持原入口；开始请求可选择“本次操作后切换”或“加入队列”。请求受理表示已经排入调度，不代表游戏目标已经完成。

征战、普通挑战和精英可在本场结果与界面收尾后让出操作权，临时玩法完成后按原运行意图恢复，保留原轮次和计数。用户明确暂停或停止的实例不会自动恢复。聚魂先准备执行场景：战斗或加载中显示等待，原生明确支持的战后退出、返回与列表关闭按正常方法执行；无法确认归属或结果的动作不自动重发。

独立日常被组织为多个玩法实例，冷却由调度器登记，到期重新读取游戏状态；需保持当前角色在线的条件继续保留。账号计划仍先保存派发边界，再提交工作流，并通过绑定的实例句柄读取结果，避免临时手动玩法覆盖账号任务的结果。

各玩法页和账号任务配置提供“资源策略”。允许消耗的资源及可选上限由用户选择；空上限表示不限。日常计划的策略是各子玩法的默认值，子玩法可以单独保存覆盖。配置保存在 `data/workflow-policies.json`，按账号和玩法隔离，不写入账号凭据文件。运行页可以把修改应用到尚未结束的实例，后续消费读取新策略，已发出动作继续核对和收尾。

当前固定接口支持的收费聚魂开局可按购买选择执行；加速和资源补足尚未接入，界面相应开关标为暂不支持。没有可确认费用或合法取消路径的原生分支会保留具体阻塞与清理状态。资源预留是消费前的保守预算占用，不冒充已经确认的支出。

命令行沿用 `run/status/pause/resume/stop`，新增：

```powershell
python -m jiangshen_assistant workflows
python -m jiangshen_assistant run soul --placement switch --option blue_count=1 --option purple_count=0
python -m jiangshen_assistant run challenge --placement queue
python -m jiangshen_assistant workflow pause <workflow_id>
python -m jiangshen_assistant workflow resume <workflow_id>
python -m jiangshen_assistant workflow stop <workflow_id>
python -m jiangshen_assistant workflow-policy soul
python -m jiangshen_assistant workflow-policy soul --file resource-policy.json
```

`run --policy-file` 仅覆盖该次请求，`workflow-policy --file` 保存后续默认值；可用 `--account-id` 设置账号专用策略。`status.play_workflows` 提供实例、场景、等待原因、目标、进度和当前能力。运行投影写入 `data/workflow-runs/`；游戏动作的启动意图和原始回执仍由对应领域记录保留。助手重启不会自动恢复旧实例或重放消费。

2026-11-12 已正常重启加载新版，并在 29-93 实机完成“积分赛 → 宝箱”的一次免费领取、奖励及宝箱关闭和返回主城。领取回包成功，奖励列表由 3 项变为 2 项；随后主城画面及新鲜场景状态均已确认。该次单项运行未触发签到页后的自动转入，也未覆盖其他工作流组合。详见[积分宝箱实机记录](data/point-chest-20261112/acceptance.md)。

## 目录与扩展

```text
jiangshen_assistant/
  app.py          # Tk 图形界面与应用协调
  core.py         # 任务状态、事件、暂停与取消；不依赖 GUI 和 Windows
  settings.py     # 配置验证与原子保存
  windows.py      # Windows 窗口与只读截图适配器
  hotkeys.py      # 全局停止按键事件与注册释放
  mono_runtime.py # 版本和进程身份校验、只读对象监测
  bridge_client.py # 固定命令、回执与会话所有权
  objects.py      # 对象连接状态与异步生命周期
  campaign.py     # 征战状态、结果去重与连续失败规则
  campaign_store.py # 本轮运行日志输出
  campaign_task.py # 征战协调、暂停、收尾与接口所有权
  development.py  # 装备/灵兽目标、资源预算与单步策略
  growth.py       # 14 类成长任务要求与能力分派
  development_task.py # 共用培养执行器、本轮回包核对及 GUI 任务协调
  runtime/win32/  # 已打包并校验哈希的调用组件
native/unity_bridge/ # 调用组件源码和离线验证
data/
  settings.json
  logs/assistant.log
  object_sessions/ # 当前调用连接的通信文件与诊断记录
  campaign_runs/  # 征战运行日志
  development_runs/ # 培养目标、动作和回包日志
tests/
```

游戏流程应放入独立任务模块，以 `RunContext.checkpoint()` / `wait()` 遵循暂停和停止协议，以 `log()` 发送日志，再由 `TaskRunner.start(name, task)` 执行。不要在后台线程调用 Tk。日常任务和战斗流程分别维护完成条件，避免把某个截图或线程正常结束误当成游戏任务完成。

界面用共用构建方法组织任务状态和操作区；页面及培养表单切换时隐藏未选项。控件使用稳定的语义名称；`current_page` / `current_development` 和 Tk 变量 `selected_page` / `selected_development` 表示选择状态，便于开发与 AI Agent 定位。操作助手时优先用导航快捷键和明确的按钮名称，先确认当前状态，再发起任务。

窗口由 Windows 适配器负责；对象监测和调用由独立控制器负责。后续业务任务需定义当前页面前置条件、正常操作、完成依据和停止条件，再接入这些能力。当前没有任意方法调用入口。
