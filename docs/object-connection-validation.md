## 已修复问题与历史记录

首轮旧版本会话 `0a41ee0f…` 的动作已正常恢复，但随后命令 49 停留在完整的 `command.txt.tmp`，正式命令仍为 48。首次异常被后续通用 UNKNOWN 覆盖，现场具体 WinError 和瞬时持锁者无法确认。20 秒租约到期后组件正常销毁，停止按钮回读 clean terminal 后释放所有权。该次失败保存在 [首轮结果](../data/acceptance/20261031-object-gui/first-session-result.json)，没有被修复后的 PASS 覆盖。

自有 Win32 文件实验复现了替换被读取目标时的 WinError 5；在该环境下，MoveFileEx 替换活读句柄的目标，即使 share7 也失败，而 ReplaceFileW 与 share7 可保留旧句柄的完整旧版本并发布新版本。修复包括：同一序号和同一字节的 0.6 秒有界发布重试、首错持久化、请求首错即停止后续轮询、共享读取，以及生产回执对既有目标采用 ReplaceFileW。永久发布失败仍保守进入 UNKNOWN，不自动重试游戏动作。

旧版 GetAsyncKeyState 当前按下状态轮询漏掉了一次真实快按 F8。最终版本改为自有线程注册热键并缓存事件，注册失败会显示停止按钮 / Esc 回退。独立审查另发现线程无法启动时可能使可选快捷键故障中断 GUI，已补异常转换和幂等关闭检查。

## 使用边界

只读字段不是服务端原子快照。调用接口限定当前支持版本和项目路径；读取或调用条件不满足时拒绝执行。恢复 UNKNOWN 时保留记录及所有权，不以删除文件或更换程序集绕过；正常退出游戏后才能解除进程边界。历史研究探针结果不替代当前组件验收，未加入任意反射调用或任何日常、战斗业务动作。
