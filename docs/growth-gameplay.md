# 成长任务与可复用培养

成长任务来自实际角色的 `newbiequests` 列表及任务模板。主界面优先选择倒序第一个未完成任务；没有未完成任务时，才选择正序第一个未领奖任务。下一项必须重新读列表，不能按任务编号加一推测。

每次启动培养或成长流程都重新读取当前游戏页面、角色任务和资源。旧培养日志及未知回包记录只用于排查，不作为启动门槛；本轮动作仍逐次核对自己的回包和资源变化。

## 已核实的规则

| 游戏功能 | 正常规则 | 助手如何调用 |
|---|---|---|
| 装备穿戴 | 成长任务检查任意装备已穿戴；正常自动装备可能从其他武将移用装备 | 固定新将教学通过游戏已有的“立即参战”和布阵确认流程处理 |
| 装备强化任务 | 任意装备强化等级达到任务 `param0`；文字可能只以主角武器举例 | 选当前阵型中已穿且归属一致的候选，逐次强化到任务要求 |
| 强化与升阶 | 下一等级费用来自真实模板；`up=1` 使用同一个正常培养按钮完成升阶 | 强化和升阶使用各自显式目标，重新读费用，不跨模式连点 |
| 铜钱 | 当前客户端的可用铜钱 getter 为两个字段之和，不能只读 32 位字段 | 使用已核实的求和规则，另核对强化石和每次实际资源变化 |
| 灵兽培养 | 可只增长经验而不立即升级；每十级经验满后走进阶分支 | 等级和经验分别判进展，正常确认进阶后再观察 |
| 灵果不足 | 客户端可能自动切到金币培养模式 | 每次重新检查果子模式；不使用金币补足 |
| 星灵激活 | 下一颗星灵按模板消耗战魂，解锁将领或技能时显示提示 | 逐次确认星灵进度和战魂扣减；不足或全部激活即停，只关闭本轮解锁提示，不进入布阵或购买资源 |
| 任务完成与领奖 | 正常检查与领奖是两个请求；本地完成标记也可能是乐观更新 | 分别跟踪检查回包、任务后置和领奖回包，不把按钮调用当成领奖成功 |

装备与灵兽的培养策略由独立领域模块实现，成长任务按自身要求调用能力；手动界面按游戏功能组织目标与预算，内部能力不作为用户选项。

## 灵兽上贡

培养页只有一个“灵兽上贡”入口。用户实际使用确认，每次固定消耗 1 颗桃子，因此界面只设置一个“上贡上限”，同时约束次数和桃子消耗。目标按阶、星设置；目标达到、用尽次数、桃子耗尽或满级，任一条件先满足即停止。取消上限后用完本轮现有桃子即停。

手动入口统一使用 `TributeTarget` 和 `SpiritTribute`。阶、星转换为 `target_level`，上贡上限映射 `max_requests`；旧 `target_tier` 仅保留内部兼容。`DevelopmentCommand.max_food` 仅用于内部固定库存校验，不再是独立用户预算。成长任务的等级能力仍由任务分派，界面不提供执行器选择。

实际消耗继续按响应 `food_consume` 和库存变化核对；每次要求消耗 1 颗桃子、0 元宝，不一致时停止且不自动重发。内部资源范围固定为本轮首次观察的库存，不随外部新增库存扩张。客户端方法参数 `1u` 没有发送到请求中；单次消耗规则来自用户实际使用确认，本次没有额外发起游戏操作验证。
